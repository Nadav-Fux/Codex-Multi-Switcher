# Changelog

## Unreleased

- Show Claude's Fable weekly quota (`seven_day_overage_included`) everywhere the 5-hour and weekly windows appear: dashboard rows, compact menu rows ("Fab") and its own Used/Left display toggle. The window is hidden when Claude does not report it, and old caches without it keep decoding. The "Model weekly" window now consistently prefers `seven_day_sonnet` and falls back to `seven_day_opus` in every read path (it used to be opus-only in the Claude Code cache reader).
- Every provider is now a true opt-in for background work: a provider turned off in Settings no longer appears in the menu (only the menu-bar icon was filtered before), is never refreshed or polled in the background — those hidden-provider paths make no network calls, helper or CLI launches, or credential reads, including the global Refresh, launch-time usage refresh, wake and timers — and produces no errors or badges. Startup profile discovery may still read existing local profile/auth state so saved profiles can be shown. Hiding Codex also unregisters the daily credential-renewal LaunchAgent and skips banked resets; re-enabling any provider starts a fresh read.
- `codex-profile renew` checks both the refresh chain and login identity before reconciling live Desktop credentials, including when a refresh adds user claims to a legacy login.
- Re-authenticating an active profile compares live auth with the bytes captured at sign-in start before replacing an existing file. Desktop can still write between the final comparison and the rename. When live auth was absent, the new file is published only if the path is still absent.
- CLI usage polling saves rotated credentials to Codex Desktop when it still holds the consumed refresh token and the login has a shared user claim or is the exact legacy input. This also applies when the quota read fails after rotation.
- Re-authenticating as a different account clears the previous account's cached usage and exhaustion override.
- Refresh All forces a Claude refresh and queues it if Claude is already busy, while respecting Claude's server rate-limit wait.
- GLM quota reads wait five minutes after HTTP 429, including when a manual refresh is requested.
- Antigravity quota no longer shows `?` when a window is unused: the quota service omits `resetTime` on a full window, and that used to discard the whole response. A partly used window without a reset time still fails closed.
- Stale sign-in healing now requires a shared user-level identity claim. On ChatGPT Team workspaces every member shares the same `account_id`, so the workspace ID alone cannot identify the user.
- The `~/.codex/auth.json` write-back prepares its temp file first, then re-reads the destination immediately before the rename and commits only when it is unchanged — narrowing the window where a login Codex Desktop saves concurrently could be overwritten to the final compare-and-rename.
- The GLM key stdin import in Local and Preview builds now writes to the same profile home the GUI reads it from.
- The app and stdin importer share a file lock so legacy Keychain migration cannot overwrite a newly imported GLM key.
- Saving or removing the GLM key writes a "no legacy migration" marker next to the key file, so a leftover Keychain item can never bring a removed key back — even when the legacy Keychain delete fails. The one-time legacy read also runs outside the store's lock, so a Keychain prompt can no longer freeze Save/Remove in Settings while it waits.
- A Claude helper reply that only needs a sign-in renewal no longer latches the permission block; polling retries after the sign-in is renewed in Claude Code.
- Claude's Refresh button now retries inside the in-memory failure backoff instead of rethrowing the last failure for five minutes; a server rate-limit wait is still honoured.
- A default Claude profile with no account metadata and no usage now shows Sign In instead of Connected.
- Antigravity settings gain a "Show all four windows in the menu bar" toggle (on by default); the per-group menu window pickers only appear when it is off.
- Antigravity shows all four quota windows (Gemini and Claude/GPT, weekly and 5-hour) in the menu bar as two columns. Google returns the Gemini group only to a versioned Antigravity client, so the request now sends Antigravity's own version. Set `antigravityMenuShowsAll` to false to go back to one window per group.
- Antigravity quota works again with the standalone Antigravity app: its local server no longer exposes a connection token, and the CLI ID-token file is gone, so the account is matched by the signed-in email in the app's storage and confirmed with Google. Quota is read from the same endpoint Antigravity uses (`daily-cloudcode-pa`), which reports the real weekly Claude/GPT usage.
- Keep Claude usage current without Keychain access: every few minutes the app runs `claude -p /usage` (no model call, 0 tokens; it switches itself off for good if a run ever reports tokens or cost), which makes Claude Code refresh its own usage cache.
- Connect and Refresh in Claude settings now take effect at once: they skip the 5-minute wait that kept showing the old "needs approval" result (a server rate-limit wait is still honoured), and a Connect clicked during a background refresh runs right after it instead of being dropped. Connect attempts are logged.
- Read Claude usage from Claude Code's own cache in its config file (`cachedUsageUtilization`, matched to the signed-in account) before asking the Keychain helper. Claude Code rewrites its Keychain login when it renews it, which dropped the helper's access several times a day; while Claude Code is in use the app no longer needs that access.
- Fixed the menu bar icon freezing on old values while Settings showed current ones: the icon is now redrawn on every change and re-pushed at least every 5 minutes, and each change is logged.
- Show Claude limit resets (full, weekly, 5-hour and Fable) in Claude settings, read from the same usage block Claude Code's `/limit-reset` uses. Display only: the app never spends a reset.
- Redesign Claude settings to match the other providers: one status banner (Connected / one-time approval / sign in) with the single action it needs, usage, then new-session controls; directory, reconnect and the statusline recorder move under Advanced. Separate Claude accounts get their usage recorder installed automatically after sign-in unless it was removed on purpose.
- Note: the stable signature keeps the Claude grant across app rebuilds while the usage helper is unchanged. A change to `CodexProfileCore` or the helper produces a new helper binary, which macOS asks to approve once.
- Sign the installed Local build with a stable identity (`Codex Multi Switcher Local Signing`, or `APP_IDENTITY`) so Keychain "Always Allow" grants survive rebuilds; packaging fails with setup instructions instead of silently falling back to ad-hoc. `APP_IDENTITY=-` opts into ad-hoc explicitly.
- Store the Z.ai Coding Plan key in a mode-600 file under the switcher home instead of the Keychain; a key saved by an older build migrates once when its Keychain item is readable. A failing legacy Keychain read is logged once, not every 30 seconds.
- Notify once when macOS blocks silent Claude usage access instead of leaving the menu bar on "?", and remove block flags left by earlier helper builds.
- Read Antigravity quotas from the standalone Antigravity app's language server (`/Applications/Antigravity.app/Contents/Resources/bin/language_server`) as well as the older IDE bundle, so Gemini quota is shown instead of the CLI-helper fallback.
- Heal Codex profiles whose saved sign-in went stale after Codex refreshed the same login. On a 401 / `token_expired` / `refresh_token_reused` (and before a banked reset when the profile's own token has expired), the app adopts a newer, still-valid copy of the same account from `~/.codex/auth.json` or another profile (same `account_id` and same user), backs up the replaced copy under `backups/auth-heal/`, and retries once. Tokens the switcher rotates are written back to `~/.codex/auth.json` when it still holds the consumed chain. When no valid copy exists, a plain "re-login needed" message replaces the raw backend error.
- Prefer fresh Claude Code bridge observations, persist account-bound polling waits across relaunches, and back off repeated quota API rate limits. Clearly mark historical menu-bar values with `~` and show the next refresh time.
- Read Antigravity's full Gemini and partner-model quota groups from the running IDE's local quota service; label missing Gemini data in the CLI-helper fallback.
- Add visible Remove Profile actions to Codex settings and preserve the selected profile through confirmation dismissal. Active profiles remain protected.
- Keep the native Claude credential read-only. Delegate expired sign-in renewal to Claude Code so the usage helper cannot replace its Keychain partition list and cause recurring password prompts.
- Added Codex CLI entrypoint discovery from `codex-package.json` for current ChatGPT app bundles.
- Retained legacy Codex Desktop CLI path support.
- Isolated this project's configuration and development auth storage under `~/.codex-multi-switcher/`.
